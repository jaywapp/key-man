# 공개 전 보안 감사 — #10

검사일: 2026-11-06. orchestrator: Codex. 기준 커밋은 `5639d41`, 작업 브랜치는 `feat/10-16-public-launch`다. 이 문서는 검사 결과이며 저장소의 Public 전환 승인이 아니다.

## 판정

검사한 Git 이력·소스·배포 고지문에서 시크릿 탐지는 **0건**이다. 실제 릴리스 설치본에 사용자 보관함, `.env`, 인증서, 디버그 심벌 파일은 발견되지 않았다. 공개를 막는 시크릿 유출 근거는 찾지 못했다.

그러나 **기존 커밋 메타데이터에 개인 메일서비스 주소 1개**, 이력 내용에 **일반 workspace 절대경로 14개 위치**가 남아 있다. Public 전환 시 이 정보도 공개된다는 점을 최종 승인에 포함해야 한다. 값은 이 보고서와 검사 출력에 기록하지 않았으며 이력을 수정하지 않았다.

## 제외 규칙·fixture·화면 자료

`.gitignore`는 `artifacts/`, `bin/`, `obj/`, `.env`, `.env.*`, `vault.json`, `*.pfx`, `*.pem` 등을 제외한다. 추적 파일 목록에서 실제 `.env`, `vault.json`, 인증서·개인 키·PDB 또는 `artifacts/` 파일은 발견하지 못했다. 제외 규칙이 이미 커밋된 이력을 지우지는 않는다.

기존 테스트의 credential은 고유 GUID와 명시적인 가짜 값으로 생성한다. UI 자료는 fixture 메타데이터와 비어 있는 PasswordBox를 사용한다. 이번 감사에서는 사용자 vault, 실제 자격 증명, 시스템 클립보드를 읽거나 변경하지 않았다. 새 GIF·동영상은 다른 작업에서 생성 중이므로 이 보고서의 기존 이미지 20개 검토와 구분하여 최종 프레임 검토를 추가해야 한다.

후속 통합 검토: 새 데모의 등록·복사·CLI/MCP 응답 프레임을 루트가 직접 확인했다. 가짜 비밀 입력은 마스킹되어 있고 실제 값·개인 경로가 없다. 전체 영상에 화면 재현 표시가 있으며 실제 자격 증명·클립보드를 사용하지 않는다. 104프레임·26초 GIF/MP4 재생성, 전체 MP4 디코딩과 문서 로컬 링크 83개 검사를 통과했다. 소스·메타데이터 응답·미디어를 포함한 최종 스테이징에도 시크릿 검사를 수행한다.

## 실제 배포 파일 확인

검사한 다운로드 EXE의 SHA-256:

```text
a473da6d53e0f01962770a451daf18103b170135c32a1680e55a95996f5998c6
```

실제 릴리스 EXE에서 설치한 payload는 실행 파일 4개, `LICENSE.txt`, 제3자 고지문 100개로 구성된다. `key-man.exe`와 `keyman.exe`는 해시가 같은 CLI 별칭이다. `.env`, `vault.json`, `.pfx`, `.pem`, `.p12`, `.key`, `.pdb` 파일은 없다. 설치 스크립트의 실행 파일·라이선스·고지문 명시 목록과도 일치한다.

`unins000.exe`, `unins000.dat`, `.keyman-isolated-test` 3개는 격리 설치 과정의 생성 파일로 분리했다. `unins000.dat`에서 탐지한 142개 workspace 경로 패턴은 테스트 설치 경로 기록이며 원본 Release에 포함된 개인정보 유출로 세지 않았다. 루트 세션이 검사를 위해 설치했고, 검사 완료 후 정상 제거했다. 로컬의 기존 `artifacts/publish`를 실제 Release payload의 대체 근거로 사용하지 않았다.

## 한계와 공개 조건

- Gitleaks는 설치 EXE 같은 바이너리를 텍스트로 검사하지 않는다. 단일 파일 실행물의 내부 압축 리소스 전체를 풀어 모든 임의 문자열을 검증했다고 주장하지 않는다. 원본 이력·소스 검사, 실제 payload 목록·고지문 검사 및 읽을 수 있는 바이너리 문자열 검사는 각각 수행했다.
- 시크릿 정규식 탐지 0건은 모든 비밀값의 부재 증명이나 독립적인 보안 인증이 아니다. 악성코드 샌드박스 분석, 외부 서비스의 키 유효성 검사, 클린 VM 전체 설치 검증도 이번 감사와 구분한다.
- 설치 EXE는 서명되지 않았다. 체크섬 일치는 다운로드 무결성 확인이며 게시자 인증이나 코드 서명을 대체하지 않는다.
- Public 전환 전 기존 Git 개인 이메일·경로 공개에 대한 최종 확인, 새 데모 및 최종 변경분 검사, 공개 다운로드·제보 채널의 실제 접근 확인이 남는다. 이력 재작성이나 원격 게시 상태 변경은 이 보고서 작성에 포함하지 않았다.

## 검사 증적

값을 제거한 결과와 패키지 해시 인벤토리는 비추적 `artifacts/launch-security/`에 보관했다. 해당 디렉터리는 공개 커밋에 포함하지 않는다.

- `gitleaks-history.json`, `gitleaks-working-source.json`, `gitleaks-installed-payload.json`
- `history-privacy.json`: 패턴 분류·파일·행·blob·관련 커밋, 이메일 값 없음
- `package-inventory.json`: 실제 asset 및 설치 파일의 경로·크기·SHA-256, 설치 생성분 표시
- `media-sheet-*.png`: 기존 이력 이미지의 내부 검토용 모음

기본 이력 검사는 아래처럼 재현할 수 있다. 검사 결과 디렉터리를 먼저 만들고 Gitleaks 기본 규칙을 사용한다.

```powershell
gitleaks git . --log-opts="--all --full-history -m" --ignore-gitleaks-allow --redact=100 --no-banner --report-format=json --report-path=artifacts/gitleaks-history.json
```
