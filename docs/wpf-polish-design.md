# WPF 화면 다듬기 설계

## 공통 원칙

`impeccable`과 `design-taste-frontend`를 확인했다. 후자는 랜딩 페이지 중심이므로 네이티브 데이터 작업 화면에는 웹 구성·애니메이션 규칙을 적용하지 않는다. WPF 기본 키보드 동작과 한글 가독성을 유지하고 Segoe UI/Malgun Gothic, 4/8 기반 여백, 의미 있는 선택·포커스·오류 색상을 사용한다. 시안에는 외부 라이브러리·이미지가 필요하지 않다.

## 비교 방향

| 시안 | 구조 | 표현 | 장점 |
|---|---|---|---|
| 1. Clear Desk | 상단 검색·목록·하단 선택 작업 | 밝은 중성 바탕, 절제한 파랑, 단정한 표 | 기존 동선과 Windows 친숙함, 권장 |
| 2. Night Console | 상단 도구 모음·목록과 우측 선택 상세 | 짙은 차콜, 선명한 청록, 조밀한 목록 | 어두운 개발 환경에서 선택 항목 확인 |
| 3. Quiet Ledger | 넓은 제목·수평 검색·여유로운 목록 | 밝은 흰색, 짙은 녹색, 글자 중심 | 적은 수의 키를 편안하게 탐색 |

디자인 변화/모션/밀도는 각각 3/1/6, 4/1/7, 4/1/4다. 모션은 선택 후 운영 구현에서 Windows 애니메이션 설정을 고려한 짧은 상태 전환으로 제한한다. 시안은 정적 상태로 비교한다.

## 시안 구현과 검증

사용자는 1안 Clear Desk를 선택했다. 운영 적용에서는 색상·버튼·입력 스타일을 공통 리소스로 통합하고 MainWindow 및 AddCredentialWindow의 기존 명령·바인딩·PasswordChanged 처리를 유지한다. 긴 이름과 메모는 툴팁으로 원문을 제공한다. 빈 목록과 검색 결과 없음은 현재 검색 상태에 맞게 안내한다. 추가 창은 폼만 스크롤하고 하단 저장·취소를 고정한다.

`docs/ux-concepts/wpf-polish/`에 .NET 10 WPF 프리뷰 프로젝트와 각 콘셉트의 독립 XAML을 둔다. 실제 앱 코드를 참조하지 않으며 인메모리 가짜 항목으로만 검색·선택·추가/삭제를 시연한다. 복사 버튼은 상태 예시만 보여 주고 시스템 클립보드에는 쓰지 않는다. 창은 기본 Windows 프레임을 유지한다.

1040×680과 820×520에서 목록 화면, 추가 창을 렌더링해 검사한다. 선택 후에는 운영 XAML의 바인딩·명령과 PasswordBox 비밀값 처리를 보존해 적용한다.
