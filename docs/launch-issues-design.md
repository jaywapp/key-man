# 공개 준비 이슈 처리 설계

## 구조

- 보안: Git refs와 이력, 추적 파일, 예시·이미지, 다운로드한 설치 파일/배포 구성물을 검사한다. 값은 출력하지 않고 건수와 분류·잔여 위험을 기록한다.
- 데모: 운영 WPF XAML과 가짜 fixture의 등록·검색·복사 흐름을 재현하여 프레임을 렌더링한다. 실제 사용자 보관함·클립보드를 사용하지 않는다. CLI/MCP 실제 fixture 응답을 비밀값 없이 보여주고 재현 영상임을 명시한다. GUI 기능을 새로 설계하지 않는다.
- 문서: README 첫 화면에 문제·대상·다운로드/소스·3가지 사용 흐름을 연결한다. 정적 이미지 폴백과 미디어 대체 텍스트, 검증 날짜·환경·한계 표를 제공한다.
- GitHub: Description과 Topics는 이슈에 제안된 값을 기존 설정과 병합한다. 비공개 상태에서는 공개 Website를 주장하지 않는다. 공개 승인 후에만 visibility·제보 기능·익명 접근 검증을 수행한다.

후속 공개 승인을 받아 Public과 비공개 취약점 제보를 활성화하고 Website를 실제 alpha1 릴리스로 연결한다. README·설치·보안 문서의 준비 상태를 실제 상태로 바꾼다. 브라우저 없이 검증한 HTTP/공유 메타데이터와 Threads 앱 내부 미리보기는 구분한다.

## 검증

에이전트별 파일 소유권을 나누고 루트가 결과를 검토한다. 데모 프레임·출력 크기·길이·텍스트 노출을 확인하고 문서 링크·시크릿 검사 및 기존 필수 CI로 통합 검증한다. 기존 공개 알파 실행 코드 변경이 없다면 설치 파일을 불필요하게 교체하지 않는다.
