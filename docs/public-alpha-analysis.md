# 공개 알파 준비 분석

- orchestrator: Codex
- 요청: 기존 공개 준비도 검토의 제안을 반영해 Threads에서 소개하고 다운로드를 안내할 수 있는 수준으로 정리한다.
- 승인 근거: 사용자가 검토 후 "너가 제안해준대로 잘 정리해줘"라고 구현을 승인했다. 앞선 데이터 보존·보안·배포·문서 개선 제안을 이번 작업의 범위로 삼는다.
- 기준: `origin/main`의 `9702545`, 별도 `feat/public-alpha-readiness` 브랜치. 기존 작업 파일 변경 없음.

## 확인한 문제

GUI의 오래된 목록 저장과 초기 로드 실패 뒤 저장이 메타데이터를 유실시킬 수 있다. importer는 0·1개 목록을 배열로 직렬화하지 않는다. CLI/MCP의 클립보드 동작과 README 설명이 다르고 MCP 강제 교체 도구의 파괴성 표기가 부정확하다. 회귀 테스트가 CI에서 빠져 있으며 main push마다 정식판을 발행한다. 마지막 CI는 아티팩트 용량 초과로 릴리스 단계에 도달하지 못했다. .NET 9 지원 종료를 앞두고 있다.

## 범위와 결정

- 기존 Windows GUI·CLI·stdio MCP의 로컬 개발용 키 관리 범위를 유지한다.
- 데이터 변경을 프로세스 간 직렬화하고 최신 목록에 변경을 적용한다. GUI 초기 로드 실패 후 쓰기를 차단한다.
- importer와 메타데이터 경계 테스트, 클립보드 수명·MCP 도구 표기를 보완한다.
- .NET 10 LTS, PR 검증, 수동 공개 알파 릴리스, 체크섬·짧은 아티팩트 보존으로 배포를 정비한다.
- 설치·사용·보안·기여 문서와 실제 앱의 가짜 데이터 데모, Threads 게시 초안을 준비한다.
- 2026-11-06 사용자가 MIT 확정 질문에 "응"으로 승인했다. KeyMan 원본 소스에 MIT를 적용하고 저장소와 설치 패키지에 원문을 포함한다. 외부 구성요소의 기존 라이선스·고지는 유지한다.
- 사용자가 후속으로 커밋·push·병합·릴리스 업데이트·README 갱신을 명시적으로 승인했다. feature 브랜치를 PR로 병합하고 통과한 main에서 `v1.1.0-alpha.1`을 발행한다. 저장소 공개 전환과 Threads 실제 게시는 이 요청과 구분해 확인한다.
- 사용자 vault 및 실제 자격 증명은 읽거나 변경하지 않는다. 테스트는 고유 식별자의 가짜 credential과 별도 메타데이터만 사용한다.

## 완료 기준

데이터 유실 시나리오의 회귀 검증, 전체 Release 빌드 및 테스트, Windows 설치 파일 제작과 격리된 설치 검증을 수행한다. README의 기능·제한과 실제 동작을 맞추고 게시 전 남은 외부 설정을 명시한다. 실제 확인하지 못한 배포·서명·클린 VM 검증은 완료라고 표현하지 않는다.

## 원격 검증 후속

PR #8의 첫 CI에서 네이티브 클립보드 변경 번호가 쓰기 완료 후 달라져 현재 복사도 삭제하지 못하는 회귀를 발견했다. 필수 검사를 유지하고 복사 표식을 검증한 후 최종 변경 번호를 확보하도록 보완한다.

수정 후 네이티브 9개 검사와 전체 CI·설치 검증을 통과해 PR #8을 병합했다. `v1.1.0-alpha.1` 발행과 실제 자산 검증 결과는 public-alpha-tasks.md에 기록한다. 저장소는 비공개이며 공개 전환 여부 질문은 미응답 상태다. 승인된 릴리스와 README 갱신은 진행하고, 비로그인 접근·취약점 제보 활성화·Threads 게시 조건은 별도로 남긴다.
